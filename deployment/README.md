# BELL Explain 私有同步伺服器

此部署提供一個個人知識庫的同步工作區。擁有同一組同步憑證的裝置可讀寫該工作區全部筆記。伺服器不執行 AI、不抓取原始 Repo，也不收集模型 API 金鑰。筆記包含你貼上的來源、教學內容、動畫資料、收藏和關聯；連線時會將現有筆記上傳到指定伺服器。Repo 索引與向量索引屬於本機可重建資料，沒有透過此筆記協定傳送。

## 本機驗證

需要 Docker Compose。在 `deployment/` 下：

```sh
cp .env.example .env
openssl rand -hex 32
```

把生成的憑證填入 `.env` 的 `BELL_SYNC_TOKEN`，然後執行：

```sh
docker compose up -d --build
```

在 BELL Explain 的同步設定填入 `http://127.0.0.1:8787` 與相同憑證。先測試連線，再勾選上傳現有筆記並連線。這個預設部署只接受同一台主機連線。

## 跨裝置與 HTTPS

將程式碼部署到自己的 Linux 伺服器、設定 DNS 指向該伺服器，在 `.env` 填入 `BELL_SYNC_DOMAIN=sync.example.com`，開放 80/443 連入，再於 `deployment/` 執行：

```sh
docker compose -f compose.yaml -f compose.https.yaml up -d --build
```

Caddy 會申請與更新 TLS 憑證。在每個裝置的 BELL Explain 填入 `https://sync.example.com` 與工作區憑證。請以自己的網域取代示例。若已有 HTTPS 反向代理，可將流量代理至 `127.0.0.1:8787`，不需 Caddy。用戶端拒絕遠端明文 HTTP，也不跟隨重新導向。

每台裝置的本機 BELL Explain 後端需要啟動，才會定期同步。瀏覽器關閉但後端仍啟動時會繼續同步；電腦離線或關機時，佇列保留在本機，下次啟動或恢復連線自動續傳。關閉同步只會清除該裝置的同步連線、憑證與佇列，保留本機和雲端筆記；再次連線會重新比對全部內容。

## 同步語意

- 每篇筆記有穩定 ID、伺服器版本與內容雜湊。判斷版本不用裝置時間。
- 每次寫入附帶唯一操作 ID 與預期版本；重送操作不會重複套用。
- 雲端透過連續游標傳回增量變更，SQLite 交易會同時保存文件、變更與操作記錄。
- 刪除保留 tombstone；其他裝置的過期編輯會顯示衝突，不會自動復活已刪筆記。
- 離線期間雙方修改會保留兩個版本，等待選擇本機、雲端或兩者。保留兩者時，雲端版本沿用原 ID，本機版本存成另一篇筆記；若雲端已刪除，原筆記保持刪除，本機內容另存副本。
- 相同內容即使時間戳不同仍可自動對齊。相互關聯可能暫時指向尚未同步的筆記，待全部變更到齊後可用。
- 伺服器端是持久化 SQLite，適合個人多裝置使用；此部署不是多租戶 SaaS，沒有使用者註冊或共編權限。

## 保護與備份

更新程式時，請讓雲端同步服務與所有裝置使用同一版本。小完整程式案例新增了情境、執行環境、逐段解說、預期輸出與應用欄位；這些欄位會與筆記一起同步。舊版同步服務或用戶端尚未認得這些欄位，可能回報內容雜湊不一致。更新雲端程式碼後，在原本的 `deployment/` 目錄使用相同 Compose 指令加上 `--build` 重建服務，保留現有資料 volume 與憑證，再更新每台裝置。既有沒有案例欄位的筆記仍可正常讀取，無須搬移資料庫。

同步憑證只儲存在本機後端 SQLite 與伺服器環境設定，不會透過狀態 API 回傳，也不儲存在瀏覽器 localStorage。HTTPS 保護傳輸；伺服器能讀取筆記內容，這不是端對端加密。請保護伺服器、備份與 `.env`，不要將它們提交至 Git。

持久資料位於 Compose 的 `sync-data` volume，停止或更新容器不會刪除。不要使用 `docker compose down -v`，除非確定要刪除資料。備份時先停止 `sync` 服務，再備份該 volume 的完整 `/data` 目錄（包含存在的 SQLite WAL 檔），完成後重新啟動。還原時也先停止服務，還原完整目錄並保留 `node` 使用者可讀寫的權限。工作區 UUID 隨資料庫保存，若以全新資料庫取代舊資料庫，用戶端會要求重新連線。

輪換憑證：更新 `.env` 的 `BELL_SYNC_TOKEN`、重建同步服務，再於每台裝置重新連線。不要刪除資料 volume。重新連線會比對內容，分歧會進入衝突處理。

協定端點：`GET /v1/info`、`GET /v1/pull?cursor=N`、`POST /v1/push` 均需 `Authorization: Bearer …`。`GET /health` 僅回傳健康狀態。
