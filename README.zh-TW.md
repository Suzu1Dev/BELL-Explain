# BELL Explain

[English](./README.md) · **繁體中文**

繁體中文與雙語的本機優先程式學習工作區：貼上程式碼、概念、文章、公開 GitHub 專案或網址，或上傳 PDF／Word／PowerPoint 文件，產生逐段解說、生活例子、程式碼與互動動畫，完成後自動存入知識庫。可單獨執行（Standalone Edition），也可與 [BELL Suite](https://github.com/Suzu1Dev/bell-suite) 串聯運作。

## 一鍵安裝與 CLI 啟動

### macOS / Linux / WSL

```bash
curl -fsSL https://raw.githubusercontent.com/Suzu1Dev/BELL-Explain/main/install.sh | sh
bell-explain
```

### Windows (PowerShell)

```powershell
irm https://raw.githubusercontent.com/Suzu1Dev/BELL-Explain/main/install.ps1 | iex
bell-explain
```

### npx / Git Clone

```bash
# 直接透過 npx 啟動
npx bell-explain

# 或從原始碼啟動
git clone https://github.com/Suzu1Dev/BELL-Explain.git
cd BELL-Explain && npm install && npm run build
./bin/bell-explain.mjs start
```

### 常用 CLI 指令

```bash
bell-explain start               # 獨立模式啟動（預設 http://127.0.0.1:3001）
bell-explain start --suite       # BELL Suite 模式啟動（預設 http://127.0.0.1:4602）
bell-explain start --port 4602   # 自訂連接埠
bell-explain doctor              # 檢查 Node、SQLite、資料目錄與 AI 模型連線狀態
```

---

1.0 版支援本機 Codex／Claude Code 模型設定、Git commit 檔案樹索引、多語語意搜尋、FSRS 間隔複習、5 產品 BELL Suite 雙向交接（含送到 Personal、Reader 與 BELL PR），以及可自行部署的多裝置筆記同步。三篇人工編寫的閉包、Event Loop、Debounce 示範不需要模型登入；自己的輸入需要連接 Codex、Claude Code 或設定 AI API。

## 快速啟動

需要 **Node.js 22.13 以上版本**與 npm，建議使用 Node.js 24。Repo 索引需要 Git；Codex／Claude 教學需要本機可執行的 Codex CLI 或 Claude Code CLI。後端使用 Node 內建 SQLite，部分版本會印出 experimental warning。

```bash
npm install
npm run dev
```

開啟 [http://127.0.0.1:5173](http://127.0.0.1:5173)。開發模式會一起啟動 Vite 前端與 `127.0.0.1:3001` API，請保留這兩個連接埠。

執行正式建置的本機版本：

```bash
npm run build
npm start
```

此時開啟 [http://127.0.0.1:3001](http://127.0.0.1:3001)。`npm start` 需要先有 `dist/` 建置檔案。

## 教學模型：Codex、Claude Code 或相容 API

### Codex

預設供應商為 **Codex**。在執行 BELL Explain 的同一台電腦完成一次登入：

```bash
codex login
```

開啟網頁的模型設定，按「重新整理」，選擇模型、推理深度與速度，再儲存。登入與模型目錄由本機 Codex `app-server` 取得，沿用該帳號的權限與額度；BELL 不讀取或複製 Codex 登入憑證，不需要另填教學用 API key。若 CLI 不在 `PATH`，可在 `.env` 設定 `CODEX_CLI_PATH` 為執行檔的完整路徑，再重新啟動 BELL。

| 設定 | 行為 |
| --- | --- |
| Model | 動態顯示目前帳號可用的教學模型，沒有寫死某個模型 ID。 |
| Effort | 依所選模型回傳的能力顯示選項；`default` 使用該模型宣告的預設推理深度。 |
| Default | 使用 `default` service tier。 |
| Fast | 模型提供對應能力時才可選，例如回傳的 `priority` tier；請求使用實際宣告的 tier ID。 |
| Ultrafast | 僅在帳號與模型明確提供對應 tier 時啟用；未提供時顯示原因並停用。 |

速度與 effort 分開設定。程式不會用降低 effort、更換模型或虛構 tier 來冒充 Fast／Ultrafast。設定保存於本機，套用於下一次生成；可用性與用量由帳號和服務端決定。

### Claude Code

使用本機 **Claude Code CLI** 的登入。在執行 BELL 的同一台電腦、一般終端機（不要在另一個 Claude Code 對話中）完成一次登入：

```bash
claude auth login
```

開啟模型設定、按「重新整理」，選擇「Claude Code」、模型與推理深度後儲存。BELL 以 `claude auth status` 確認登入狀態，不讀取或複製 Claude 登入憑證；用量計入該帳號，可用模型與額度依訂閱方案而定。若 CLI 不在 `PATH`（例如 systemd 服務），在 `.env` 設定 `CLAUDE_CLI_PATH` 為執行檔完整路徑，再重新啟動 BELL。

| 設定 | 行為 |
| --- | --- |
| Model | Claude Code 沒有模型目錄 API，BELL 內建 Claude Opus 5.5（預設）、Claude Sonnet 5.5、Claude Haiku 4.5 的完整模型名稱。帳號方案不支援所選模型時，生成會回報錯誤；Opus 5.5 需要 Claude Code 2.1.280 以上，版本過舊會提示執行 `claude update`。 |
| Effort | Opus／Sonnet 提供 low、medium、high、xhigh、max；`default` 依 Anthropic 文件傳入該模型預設值（Opus 5.5 為 medium、Sonnet 5.5 為 high）。Haiku 4.5 不支援 effort，不傳此參數。 |
| Speed | 只提供 Default。非互動模式沒有可指定並驗證的加速選項，Fast／Ultrafast 顯示為不可用；若 CLI 回報已開啟 fast mode，工作會停止。 |

每個階段啟動獨立的 `claude -p` 程序與暫存目錄，使用 `--safe-mode`（略過 CLAUDE.md、skills、plugins、hooks、MCP 與自訂代理）、`--tools ""`、`--strict-mcp-config`、`--permission-mode dontAsk` 與 `--no-session-persistence`，以 `--system-prompt-file` 取代 Claude Code 預設提示詞；來源資料只經 stdin 傳入。子程序只繼承登入、網路與語系所需的環境變數，不會取得 BELL 的 API key 或同步 token。啟動回報的模型、工具、MCP、插件（CLI 內建者除外）、skills 或權限模式不符，或回覆中出現工具呼叫、其他模型時，工作會停止。effort 無法從 CLI 回報核對。

### OpenAI 相容 API

也可使用支援 **Chat Completions** 與 `response_format: {"type":"json_object"}` 的 OpenAI 相容 API。將 `.env.example` 複製為 `.env`，填入以下值、重新啟動，再於介面選擇「OpenAI 相容 API」並儲存：

```dotenv
AI_BASE_URL=https://api.openai.com/v1
AI_API_KEY=你的金鑰
AI_MODEL=供應商支援的模型名稱
```

API 模式使用環境設定的模型，effort 與速度維持供應商預設。可使用 HTTPS 端點，或 loopback HTTP 模型端點；本機端點也需要非空的 `AI_API_KEY` 與 `AI_MODEL`。介面顯示 API 已設定代表設定存在，不能證明金鑰、額度或模型可用。

### 三個代理與資料傳送

一次教學依序執行分析、教學、整理三個代理。Codex 與 Claude Code 模式的隔離方式見上文；Codex 模式每階段建立獨立的 `app-server` 程序、暫存目錄與暫時對話，要求唯讀、關閉 shell／網路工具／MCP／插件／子代理等能力，只處理 BELL 提供的文字；回傳的模型、tier 或隔離設定不符時會停止。API 模式使用三次獨立的 system/user 訊息。來源資料不賦予工具執行能力。

教學會把當次來源、前一階段產物及整理階段選入的既有筆記摘要傳至所選模型服務；費用與額度依帳號或供應商計算。

## 上傳文件並解說

首頁選「檔案」，拖入或選擇 **PDF、DOCX、PPTX、TXT、Markdown**，確認文字預覽後選擇解說範圍、填寫想理解的重點與學習深度。檔案解析不需要模型登入；開始解說後，沿用目前選取的 Codex／Claude／API 模型，依序分析、教學、分類與建立關聯筆記。

- 每個檔案最多 **50 MB**；PDF 最多解析前 **1,000 頁**、PPTX 前 **200 張投影片**，全文最多保存 **1,500,000 字元**。Word 與純文字依邏輯段落編號，最多 10,000 段；不把 Word 段落冒充頁碼。PPTX 依簡報中的實際投影片順序讀取。
- 檔案在獨立子程序解析（PDF 最多等待 120 秒，其他格式 30 秒），可取消與重試。舊格式 `.doc`／`.ppt` 與加密 Office 文件不支援，請另存為支援格式。
- **PDF 擷取品質**：依文字座標重組行與段落，中文不插入多餘空白，跨行的英文斷字會接回，程式碼保留縮排；出現在多數頁面上下邊緣的頁首、頁尾與頁碼會移除。Noto／思源等字型匯出的 PDF 常把「行、一、工」等字擷取成康熙部首碼位，BELL 依 Unicode 對照表還原成一般漢字，避免搜尋與段落挑選漏字。多欄版面會逐頁偵測欄間空白：標題、全寬摘要、跨欄圖說或公式等跨欄文字把頁面分成上下區段（超出欄寬的長網址不算），每段先讀完左欄再讀右欄（三欄依序類推），從左欄底部延續到右欄頂端的段落與斷字會接回，下一欄頂端的標題則另起一段；只有各欄都是排滿欄寬的成段文字才重排，投影片、表格、程式碼、以單欄文字為主且並排內容下方仍接著跨欄文字的頁面（例如講義裡夾在段落之間的並排表格）、上下欄位之間夾著無文字全寬圖片的區段，以及其他無法判斷的頁面，都維持 PDF 內容順序，解析預覽會提示偵測為多欄的頁數。欄內有大型圖表、圖文交錯或文字框位置特殊的頁面，可能維持原順序或判斷錯誤，仍需對照原檔。文字層裡的公式常散成零碎符號，模型只在能從上下文或頁面影像確定原式時，才改寫成可排版的 LaTeX 公式，否則會說明無法判讀。
- **解說範圍**：可選整份文件、指定頁碼（或投影片、段落範圍），PDF 有書籤時也能直接選章節。範圍內的文字超過 **42,000 字元**時，依提問挑選相關段落並兼顧前、中、後內容；筆記來源會標示實際選取位置及截斷情況，這不代表模型逐頁讀完長文件。
- **頁面影像**：PDF 預設勾選「附上頁面影像」，BELL 在伺服器把範圍內沒有文字層的掃描頁，以及含圖片或大量向量圖形的頁面轉成影像（每次最多 **8 頁**、長邊 1,400 px），連同頁碼交給分析與教學代理，讓模型閱讀圖表、公式與掃描內容；整理代理不接收影像。影像只用於當次解說、不保存，會增加用量與等待時間。Codex 與 Claude Code 支援影像；相容 API 需所選模型支援 Chat Completions 影像輸入，否則請關閉此選項。只有掃描頁而沒有文字層的 PDF 也能上傳，但必須附上頁面影像才能解說。
- **選頁更聰明**：上傳 PDF 時檢查每頁的圖片、向量圖形與文字行中的空白，並扣掉版型：同一張圖片在多頁重複使用（標誌、背景、外框，pdf.js 會標示為共用）不算圖表，向量圖形與文字空白則以幾乎每頁都有的數量為基準，只有超出版型的頁面才算含圖表；不同的圖表即使尺寸相同仍各自算數，少於 5 頁的檔案則以最空白的一頁為基準；以圖形繪製、在文字層留下空洞的公式（例如 PowerPoint 匯出的方程式）也會被找出來。解說時每次 8 頁的影像額度優先給掃描頁，其次依圖表與公式的程度排序，額度用完時在來源範圍說明哪些頁面只依文字層。舊版上傳的檔案在第一次開啟時於背景補做這項檢查（加密 PDF 要等輸入密碼附上頁面影像或深度解析時才檢查）。
- **深度解析**：檔案區的「深度解析」會呼叫目前的模型（Codex、Claude Code，或所選模型支援影像輸入的相容 API），把含圖表、公式或掃描內容的頁面逐頁讀一次（每次呼叫 4 頁、影像長邊 1,600 px），依閱讀順序轉寫文字（多欄先左後右、表格轉成 Markdown 表格、數學式寫成 LaTeX，程式碼照頁面原樣、不另加反引號），並說明每張圖表、示意圖與公式在呈現什麼；結果存在檔案旁的 `readings.json`。之後的解說與依問題選頁都改用這份轉寫，這些頁面也不再佔用影像額度；來源範圍會註明哪些頁面使用模型轉寫、可能有辨識錯誤。每完成一批就保存，停止或逾時（上限 2 小時）不會丟失已完成的頁面，再按一次會接著解析剩下的頁面；一次最多 120 頁。深度解析在伺服器上執行，離開頁面不會停止，右下角顯示進度並可停止；同時只解析一份檔案，不佔用教學的名額。加密 PDF 需輸入密碼，密碼不會保存。按鈕會標示預估的模型呼叫次數。
- **密碼保護 PDF**：上傳時會詢問密碼，密碼以請求標頭送到伺服器，只經 IPC 交給解析子程序，不寫入磁碟或筆記；附上頁面影像時，瀏覽器會在同一次草稿中再送一次密碼。之後在檢視器開啟原檔，密碼只在瀏覽器內由 pdf.js 使用。
- **並排閱讀**：PDF 筆記左側是原文檢視器（可縮放、跳頁、選取文字），右側是解說；解說中的「第 N 頁」與每段的頁碼標籤可點擊跳頁，勾選「跟著解說翻頁」時，點選或捲動到段落會自動翻到該段引用的頁面。互動圖解移到左側「圖解與相關」分頁。窄螢幕改為「解說／原文 PDF／圖解」切換。檢視器在需要時才載入 pdf.js。
- 原始檔案及擷取文字保存在 `data/documents/`。筆記的原始內容頁可檢視引用文字，並從上傳它的伺服器下載原檔。完成的解說、檔名與當次來源文字會加入知識庫搜尋；未選入解說的段落與頁面影像不會加入筆記索引。
- 雲端筆記同步與 Markdown 匯出包含解說、檔案資訊、引用文字及讀取範圍，**不包含原始附件或其他未選取的擷取文字**。在同一個 Ubuntu 網址登入 Tailscale 使用的各裝置共用原檔；獨立 BELL 部署同步後會顯示僅有來源快照，並排檢視器也會提示沒有原檔。同步端需更新至相同版本，舊版會拒收超過舊上限（20 MB、200,000 字元）的檔案筆記。

## Repo 索引與引用

「Repository 工作區」接受公開 GitHub 根網址，或使用者明確指定的本機 Git repository **根資料夾絕對路徑**。它固定一個 commit、遞迴遍歷整棵已提交檔案樹、記錄每個檔案的收錄或排除原因，再將合格文字檔分段索引；可查看內容、commit、路徑與行號。建立索引不需要教學模型登入。

- 公開 GitHub：接受 `https://github.com/owner/repo`，抓取遠端 HEAD 的淺層 Git 資料；不 checkout、不執行原始碼、不初始化 submodule。
- 本機 Git：必須有可讀取的 `HEAD` commit，且路徑是 repository 根目錄；不會向上搜尋別的專案，不包含未提交或未追蹤檔案。Bare repository 也可讀取。
- 排除二進位、非 UTF-8 內容、相依套件／產生目錄、壓縮與媒體檔、套件鎖定檔、常見憑證檔名、符號連結及 submodule。排除規則不是完整的機密內容偵測器。
- 每個專案最多索引 **10,000 個合格文字檔、50,000,000 bytes 文字、60,000 個分段**；每檔最多 **250,000 bytes**，遠端 Git 下載上限 **300,000,000 bytes**。Git 檔案樹／輸出也有大小限制；超限會標示範圍不足或索引失敗。
- 「更新版本」會保留舊 commit，另建新索引；「移除此索引」只移除該版本索引，保留已儲存筆記的來源快照。
- 索引工作持久保存進度，可取消、重試及在重啟後續跑。取消教學不會自動刪除或取消獨立索引工作；需要時請在 Repo 工作區按「取消」。

「完整索引」指遍歷完整 commit 檔案樹並在上述規則與容量內收錄合格文字檔。畫面顯示總項目、已索引、排除數與限制，不能把部分收錄當成完整分析。每次新提交 GitHub 網址會解析當時的遠端 HEAD；在工作區選擇既有索引提問，會沿用該固定 commit。

生成 Repo 教學時，從索引檢索相關分段，同時保留 README、主要程式與建置入口的涵蓋，避免長篇報告佔滿來源。來源上下文最多 42,000 字元，保留 `path:Lx-Ly @ commit` 引用。**索引整個專案不等於模型一次讀完全部檔案**；筆記來源會記錄當次實際使用的分段數與涵蓋範圍。

## 真實多語向量與關聯閱讀

在設定中按「啟用本機語意模型」，首次會下載 `Xenova/paraphrase-multilingual-MiniLM-L12-v2` 的固定版本與 q8 權重，下載量約 120–150 MB，可能需要數分鐘。之後以本機 CPU 計算向量，模型快取與向量保存在本機；此本機向量功能不會把筆記或程式碼內容傳到模型下載站。

筆記與 Repo 都會分段建立真正的語意向量。建立完成後，跨筆記／程式碼搜尋與段落旁的相關閱讀結合向量相似度與關鍵字，畫面標示「語意＋關鍵字」。尚未啟用、建立中、模型失敗或查詢失敗時，使用並標示「關鍵字搜尋」，不會把詞彙比對宣稱為語意向量結果。可查看建立數量並重建；模型版本與內容雜湊用來避免混用過期向量。

向量保存於 SQLite，搜尋在本機計算相似度；目前適用個人知識庫，沒有分散式向量叢集或近似最近鄰索引。資料量增加時，向量建立時間、查詢時間與記憶體用量也會增加。

也可另外使用 OpenAI 相容的 **Embeddings API**。在 `.env` 設定後重新啟動，再於向量設定中啟用 API：

```dotenv
EMBEDDING_BASE_URL=https://api.openai.com/v1
EMBEDDING_API_KEY=你的向量服務金鑰
EMBEDDING_MODEL=供應商支援的向量模型名稱
```

`EMBEDDING_BASE_URL` 選填，預設如上，必須使用 HTTPS。API 向量會把已收錄的筆記／程式碼段落與查詢文字送往該服務，並可能產生費用。向量模型與 Codex 教學模型是兩個獨立設定，不會把 Codex 對話模型當作 embeddings API。

## 筆記、動畫與來源範圍

- 逐段文字、程式碼與白話例子；點選段落，旁邊的動畫步驟與相關閱讀跟著切換。
- 新教學至少包含一個實作案例：使用情境、執行環境、內容、對應行號的白話拆解、預期結果與實際用途。案例依主題使用實際會遇到的格式：程式與演算法用可執行小程式（附逐步狀態與時間／空間複雜度）、雲端用 IAM 政策 JSON 或 task definition、網路用訊框／封包十六進位傾印並逐位元組解讀、組合語言附暫存器追蹤表；依一般知識撰寫的公開格式會註明未對照最新官方文件。點選拆解步驟會標亮對應行；結果由模型推導，平台不會執行案例。
- 解說深度有明確定義並直接交給分析與教學代理：「從零開始」第一次出現的術語與縮寫都會解釋；「我有些基礎」（預設）補上不變量、邊界條件、複雜度與實際格式；「深入原理」再加入正確性論證、取捨與失敗模式。每種來源都可以填「想弄懂的重點」；來源類型與深度會記在這台瀏覽器。
- 尚無案例的既有 AI 筆記會顯示「補上實作案例」按鈕，按下才呼叫模型，為合適段落補齊並保存，保留原有解說、動畫與既有程式碼（既有程式碼由伺服器保留，模型只補說明）；內建示範不提供。同時最多補齊一篇，失敗可再按一次重試。生成期間若筆記內容已修改或刪除，這次結果不會覆蓋新內容。案例同樣納入搜尋、Markdown 匯出及筆記同步。
- AI 分類、標籤與段落關聯，自動儲存、搜尋、收藏、刪除及 Markdown 匯出。
- **數學公式**：摘要、段落、白話案例、圖解說明、自我檢查、複習卡片與詞句解說裡的 LaTeX 以 [KaTeX](https://katex.org/) 排版。行內寫成 `\( … \)`、獨立成行寫成 `\[ … \]`，獨立公式可以跨行（`\[` 與 `\]` 各自單獨一行，中間不空行；只在句中提到這兩個符號的文字不會被當成公式）；`$` 一律不當公式符號，`$PATH`、價格照原樣顯示。程式碼區塊、實作案例的預期結果、反引號裡的程式碼與詞句解說的「小例子」保留原文；模型被要求把文字中的程式碼、指令與正規表示式放進反引號，沒有反引號但看起來像程式碼的片段（例如 `grep '\[ERROR\]'`、`s/\(.*\)/`、`\(\d+\)`）也照原樣顯示，不當成公式，從這類片段反白的詞句在解說卡標題與複習卡題目上同樣照原樣顯示；`1+2+...+n` 的刪節號、中文之間的 `/`、`-` 與 `\text{"abc"}` 裡的引號仍算公式。筆記標題、副標題、動畫標題與步驟標題若含 LaTeX 或反引號（例如較早產生的筆記）也會排版；模型仍被要求在這些欄位用純文字寫數學，因為標題也會出現在分頁標題、通知與知識圖譜等只能顯示純文字的地方。節點名稱與步驟的輸出不排版。LaTeX 寫錯時顯示原始文字並標示。模型只在真正的數學式使用這種寫法。每個公式只畫在自己的範圍內，負間距或 `\llap` 這類指令蓋不到旁邊的文字；獨立公式在自己的區塊內完整顯示，總和符號下較寬的範圍（`\mathclap`）不會被裁掉。KaTeX 與字型隨應用程式打包、不經 CDN，排版程式與字型第一次遇到公式時才載入；下載失敗時公式先顯示原文並提示，約兩分鐘內自動重試四次（每次換用新的網址，因為瀏覽器會記住失敗的模組下載），仍失敗就停止重試並提示重新整理頁面。反白選到公式的一部分時，會以整個公式的 LaTeX 原文作為詞句與引文；Markdown 匯出保留 LaTeX 原文。
- **行內程式碼**：上述欄位裡用反引號包住的程式碼（例如 `grep -n`）以等寬字型顯示，反引號本身不顯示；用兩個反引號包住的程式碼可以含單個反引號，沒有成對的反引號照原樣顯示。程式碼區塊與實作案例的預期結果不受影響。反白程式碼的一部分（例如指令裡的一個參數）時只以選到的文字作為詞句；選到整段或超出程式碼範圍時，以含反引號的整段作為詞句，解說卡標題與複習卡題目也顯示成程式碼。詞句標記畫在程式碼裡被解說的那幾個字上，同一段指令裡的多個參數各自有標記；跨過程式碼邊界的舊詞句（這項功能之前存的）分成程式碼內、外兩段標記，不會蓋掉同一段程式碼裡的其他標記，複習卡挖空時則連同整段程式碼的反引號一起挖掉。成對的反引號必須在同一行，所以單獨出現的反引號不會和下一行的反引號配成程式碼；只有從行首開始、到另一行行首結束的三個以上反引號（程式碼區塊）可以跨行。複習卡上的段落內容和筆記一樣逐行分段顯示。Markdown 匯出保留反引號。
- **搜尋結果標題**：筆記與段落標題照筆記排版；標題後面的詞句解釋與檔名照原樣顯示，和筆記裡的顯示方式一致。
- **先想再看**（預設開啟，閱讀頁右上角切換，記在這台瀏覽器）：實作案例的預期結果先收起，可寫下預測（不會儲存）再揭曉並對照；最後一步拆解先請你用一句話說明；手動切換動畫步驟時，這一步會改變的節點值、說明與輸出先顯示為「?」，按「揭曉這一步」才出現。自動播放時不隱藏。
- **相關筆記**：摘要下方列出整理代理確認的跨篇關聯（延伸閱讀）、其他筆記指向本篇的關聯（被引用），以及追問延伸的上下篇，每項直接寫出關聯理由；知識圖譜以實線畫出筆記關聯、點線畫出延伸關係，Markdown 匯出也附上「相關筆記」。
- **自我檢查**：筆記底部的題目先請你用自己的話寫答案，按「對照講解」才呼叫模型：模型依筆記內容寫出參考答案與 2–4 個要點、判斷答對／部分正確／還沒答到、用一兩句話指出缺漏，並列出該回頭看的段落（點了直接捲到那段）。參考答案會保存，之後再寫一次可直接對照並自評，不再呼叫模型；也可再請模型批改新答案。空白送出記為「直接看了答案」。沒答對的題目會排進今日複習。同時最多批改兩題，等待上限與詞句解說相同；未連接模型時只能先寫答案。
- **今日複習**：側邊欄與首頁顯示待複習張數。卡片由筆記自動產生——段落回想（看標題說出重點）、詞句填空（已存的詞句解說，原句挖空），以及自我檢查沒答對的題目；排程使用 FSRS（[ts-fsrs](https://github.com/open-spaced-repetition/ts-fsrs)，目標記憶保留率 90%）。每篇筆記每天最多加入 3 張新卡、全部最多 15 張，並把不同分類交錯出題；新卡與答錯的卡會在幾分鐘的學習步驟內再出現一次。先回想，按空白鍵或 Enter 翻開，再按 1–4（重來／困難／良好／簡單）評分，按鈕下方標示各自多久後再出現；「回到筆記這一段」直接打開對應段落。筆記段落或詞句解說刪除時，對應卡片一起移除；內建示範不產生卡片。複習紀錄存在伺服器的 `learning.sqlite`，同一台伺服器的所有裝置共用，不經過多裝置筆記同步。「一天」依 `BELL_TIMEZONE`（預設 `Asia/Taipei`）計算。
- **追問延伸**：自我檢查題旁的「延伸成新筆記」會沿用原來源預填首頁（PDF 沿用同一份檔案、Repo 沿用同一 commit 的索引、程式碼與文章沿用原文、網址重新讀取），問題放進「想弄懂的重點」，並標示「延伸自《…》」；生成時把原筆記的標題與摘要交給模型，從那裡接著講，不重講基礎。加密 PDF 需重新輸入密碼才能附上頁面影像。
- **繼續閱讀**：點選或捲動到的段落會寫進網址並記在這台瀏覽器，首頁顯示最近讀到的段落與進度，一鍵回到原處。已有自己的筆記後，首頁不再顯示內建示範的入口。
- 內建五種互動動畫場景：資料流程 `flow`、互動時序 `sequence`、記憶體參照 `memory`、分層架構 `layers`、事件歷程 `timeline`；節點關係有明確方向，步驟可描述連線、數值與佇列狀態。
- 播放、暫停、重播、拖曳步驟與 0.5–2× 速度調整，支援系統「減少動態效果」。點選節點可看完整值、前一步狀態、項目與關係；「放大動畫工作室」提供寬畫布，Esc 關閉並恢復焦點。既有閉包、Event Loop、Debounce 示範仍可閱讀。
- 2×2 魔方主題可附帶專用空間圖解：立體角塊、位置對照、R／B／D 轉面、輸入字串與 `rank_state` 同步更新，以及 BFS 逆操作路標。繪圖使用與 minirubik 固定參照模型對應的數學規則；搜尋圖僅展示少量鄰居，「沿路還原」反轉操作歷史，不執行完整 BFS。圖解跟隨指定段落切換，支援放大、鍵盤與減少動態效果，設定也保存至筆記、同步及 Markdown 匯出。
- 桌面右側圖解與相關閱讀可獨立捲動，不必先捲完文章；平板與手機使用一般頁面捲動。通用圖解在窄欄以單欄呈現，優先顯示本步解說與播放控制，詳細節點資訊可展開。
- 左上方的側邊欄按鈕可將桌面導覽收合為圖示列，保留主要導覽與設定入口；瀏覽器會記住收合偏好，同一網站的分頁也會同步。手機維持可開關的抽屜選單。
- 在引導解說的文字、白話案例或程式碼行內反白詞句，可點「解釋這段」或按 Alt＋Enter，呼叫目前設定的模型，依局部語境補充白話解說與比喻。每次可選最多 160 個字元，選取範圍須在同一段文字內。完成後自動存成筆記中的底線標記；以滑鼠懸浮、鍵盤聚焦或手機點按即可重看，重看不再呼叫模型。可取消等待、重試或移除已存解釋；每篇最多保存 100 則，並納入搜尋、Markdown 匯出與筆記同步。同一詞句在同一來源欄位沿用已存解說，不會套用到其他筆記。

動畫由受驗證的宣告式場景資料交給內建 SVG/CSS 元件繪製，通用場景每張圖最多六個節點、十二個步驟。模型描述的是教學推導，不是執行程式取得的追蹤紀錄；不執行模型提供的 HTML／SVG／JavaScript，也沒有自動產生照片、影片或任意動畫程式的功能。

| --- | --- |
| 程式碼、文章 | 只讀取貼上的文字，不執行程式或追蹤內文連結。網頁輸入上限 30,000 字元。 |
| 概念 | 使用模型知識編寫教學，不會自動上網查證。 |

一般網頁讀取會檢查 HTTPS 與公開 IP、固定已驗證的 DNS 位址並重新驗證重新導向。Repo 則使用限定公開 GitHub 來源的 Git 傳輸，或使用者指定的本機 commit。

最多同時進行兩個教學工作。單次教學最多三十分鐘；Codex 與 Claude Code 每階段最多十五分鐘，相容 API 每次請求最多七十秒。補齊舊筆記案例的整體上限為二十分鐘。這些是等待上限，不是預估所需時間；模型、effort 與速度仍使用你的設定。模型生成等待期間每五秒更新目前階段與經過時間；Codex 與 Claude Code 的活動通知會顯示正在思考或已接收多少回覆字元，超過三十秒沒有新活動時會明確顯示仍在等候下一次回應，不宣稱完成百分比。進度不包含模型的推理原文或未驗證的 JSON。逾時與使用者取消會分別提示。

教學與補齊案例在伺服器上執行，不依附送出請求的頁面：關閉分頁、重新整理、手機鎖螢幕或網路短暫中斷都不會停止，連線恢復後只補收錯過的進度，在同一個分頁重新整理會接回自己開始的工作；其他分頁或裝置只在右下角顯示「其他頁面正在解說」與完成通知，不會被鎖住，也不能取消別人的工作。生成期間仍可編輯輸入框、閱讀其他筆記（正在使用的檔案不能移除或更換）；不在首頁時右下角顯示進度，完成後以通知提供「打開筆記」，不會把你從正在讀的頁面帶走；仍在首頁時才直接開啟新筆記。要停止教學或補齊案例請按「取消」——離開頁面不再取消，工作會繼續使用模型額度直到完成。結束的工作保留 15 分鐘可重播進度，之後一天內仍能查詢結果，所以手機睡了很久再醒來，也會得知筆記已儲存；查不到結果時會請你到知識庫確認，不會斷言沒有儲存。工作只存在記憶體：服務停止時先拒絕新工作，再最多等待 `BELL_DRAIN_SECONDS`（預設 10 秒）讓工作完成，其餘以「伺服器正在重新啟動」結束，不會留下不完整筆記。詞句解說與自我檢查批改各有兩個獨立名額，不受教學佔用；詞句解說仍會在關閉頁面時取消。

Codex 與 Claude Code 輸入上限 100,000 字元，相容 API 為 80,000 字元；字元數不等於 token 數，模型上下文限制仍可能更小。格式錯誤、模型錯誤或提交前取消不會儲存不完整筆記；SQLite 提交成功後才通知瀏覽器完成。模型回覆的結構有問題時，伺服器先自行修正可確定的編號與引用（段落 id、超出範圍的步驟、無效或重複的節點與連線 id 連同引用一起改名、步驟中指向不存在節點或連線的引用；不改動內文，也不猜程式碼行號），仍不符合時把出錯的欄位路徑交回同一個代理，只要求修正那些位置，最多兩輪；兩端不存在或指向自己的連線先交給代理修正，最後仍無法修正時才捨棄這些連線，其餘問題修正後仍不符合才放棄。整理代理失敗或逾時時，以分析代理找出的關鍵概念作為分類與標籤、不建立關聯，筆記照常儲存。補齊案例時只捨棄有問題的個別案例。

筆記依建立時間排序，收藏不改變順序。知識圖譜以分類／標籤與筆記關聯呈現，最多顯示最新十八篇與五個主要標籤；語意檢索另由向量搜尋負責。整理代理選入最新四十篇筆記的有限摘要，摘要總預算為 14,000 字元，因此自動整理並非每次重新推理整個知識庫。

## BELL Suite 前端交接

- 側欄的九點切換器使用同源 `GET /api/suite/manifest` 回傳的 `links`。只有已設定且通過 loopback／自家 tailnet 驗證的 Personal 與 PR 來源可點；API 尚未提供或姊妹產品未設定時顯示「尚未設定」，不把離線或未知狀態當成在線。切換器支援 Tab、方向鍵與 Esc，窄螢幕在頂列提供同一入口。
- `#/explain?text=&title=&from=personal&back=` 接收 Personal 的文字交接，文字最多 2,000 字、標題最多 120 字。頁面先以 `replaceState` 移除網址內容，草稿只存於這個分頁的 `sessionStorage`；重新整理、同分頁新交接、畸形編碼與取消不會混用舊草稿。內容可編輯，**按下「開始解釋」才會呼叫模型**。合法的已配置來源與相對 hash 回程才顯示回程列。
- 筆記與複習卡的「送到 Personal」先顯示內容與來源，再開啟 `#/tasks?draft=…&from=explain&back=…` 的可編輯待辦草稿；這個動作不會建立待辦，也不宣稱建立成功。瀏覽器可見的 fragment 內容仍有被歷史紀錄、分頁或其他本機軟體讀取的風險，不應交接秘密。
- 複習數量分成載入、成功、過期與錯誤；讀取失敗顯示「—」與重試，不再把未知顯示為 0。主要學習頁面支援亮／暗色，設定保存在這台瀏覽器，並尊重系統減少動態效果。
- Suite 前端單元測試可另跑 `npx tsx --test src/lib/suite.test.ts`。共享互動稿與 tokens 的設計來源在 `bell-suite/design/`，各產品保留帶版本註記的小副本；mockup 的示範資料不代表實際 API 已連線。

## 多裝置筆記同步

已包含可自行部署的同步服務與網頁設定介面，**尚未替使用者部署任何公開雲端服務**。填入自己的服務網址與工作區憑證，先測試連線，再勾選「連線後將本機筆記同步至此服務」。測試連線不會上傳筆記。

同步筆記的來源快照、文字／程式碼教學、動畫資料、分類、標籤、關聯與收藏。**上傳的原始附件、Repo 原始索引、Git 快取與向量索引不會同步**；其他裝置可重新建立所需的 Repo 索引與本機筆記向量。

同步使用穩定筆記 ID、伺服器版本、內容雜湊與增量游標，並保留持久離線佇列。相同操作可重送；刪除保留 tombstone，過期離線編輯不會直接復活筆記。雙方修改同一筆記會保留衝突，待使用者比較後選擇本機、雲端或保留兩者；保留兩者時，本機內容另存副本。

本機後端啟動時自動同步，離線時保留待送變更。憑證只由後端保存，不放在瀏覽器 localStorage，也不由狀態 API 回傳。遠端必須使用 HTTPS，本機測試允許 loopback HTTP；伺服器可讀取筆記，此協定不是端對端加密。單一服務對應一個個人工作區，持有相同憑證的裝置可讀寫整個工作區。

用 Node 啟動獨立同步服務時，在 `.env` 設定至少 32 字元、無空白的 `BELL_SYNC_TOKEN`（可用 `openssl rand -hex 32` 產生），然後執行：

```bash
npm run sync:server
```

預設監聽 `127.0.0.1:8080`，資料庫為 `data/cloud-sync.sqlite`；可用 `HOST`、`PORT`、`BELL_SYNC_DB` 調整。它是與教學 API 分開的程序。

**新格式筆記（`BELL_LESSON_V3=1`）的上線順序**：同步服務 → 每一台裝置都更新到這個版本 → 網頁的新格式閱讀畫面上線 → 最後才開啟 `BELL_LESSON_V3`。只要共用的同步服務裡出現任何一篇新格式筆記，或標示「整理失敗」的筆記，還沒更新的舊版裝置就會整個停止同步（收不到、也送不出），直到更新為止；舊版程式無法從這邊修正。同步服務還沒更新時，新版裝置會把這些筆記留在本機，其他筆記照常同步。

**整理成新格式**（`POST /api/lessons/:id/reformat`，本文可帶 `{"depth": "beginner" | "intermediate" | "advanced"}`，預設 `intermediate`）：用筆記保存的原始內容重跑新格式生成，成功才原地覆蓋。筆記 id、建立時間、收藏、延伸自哪篇與原有的關聯都保留；詞句解說只要引用的文字還在新內容裡就搬過去（其餘不搬，進度訊息會說幾則），複習排程跟著保留；舊格式的段落卡與理解檢查卡會移除，改由新步驟的回想題取代。其他筆記連到第 N 段的關聯改指第 N 步，沒有對應步驟的照舊。「整理失敗」標示會清除。試寫兩次仍不合規範、原始內容太長、請求過於頻繁、模型出錯，或整理期間筆記被修改時，原筆記完全不變，錯誤訊息說明原因。`BELL_LESSON_V3` 未開啟時回 409（`/api/config` 的 `lessonV3` 讓網頁決定是否顯示這個選項），沒有原始內容的筆記回 422，精選示範回 400（網頁不會在精選示範上顯示這個選項）；沒有可用的模型連線時回 503 並帶 `"code": "no_model"`，網頁據此提示到設定連上 AI，而不是請使用者稍後再試；已是新格式的筆記直接回傳原筆記，不呼叫模型。整理後的筆記同樣受上面的上線順序限制：同步服務還沒更新時會留在本機等待。

**退回舊版會刪掉回想卡**：新格式筆記每一步的回想評分（〔記得〕／〔不確定〕）存在 `learning.sqlite` 的複習卡片與評分紀錄裡，沒有升級資料庫格式，所以退回加入回想題之前的版本（例如 `f4987de`）仍然打得開這個資料庫；但舊版第一次打開複習佇列時，就會刪掉所有回想卡（只顯示待複習張數不會刪）。評分紀錄會留下來，評分當天退回的話，舊版會把它們都算進「今天已複習」；之後再升級回來也找不回這些評分，那些步驟會變回還沒回答，可以重新評。提交 `ab4f7cc` 的說明寫「older app versions can still open the database」，只說對了「打得開」這一半。還沒有人在筆記裡評過回想題時，退回不會少任何資料；評過之後要退回，請先備份 `learning.sqlite`，升級回來時再用備份還原（退回期間的複習紀錄會因此不見）。

Docker 部署請先在 `deployment/` 複製 `.env.example` 為 `.env` 並填入自己的同步憑證，再執行：

```bash
cd deployment
docker compose up -d --build
```

預設服務位於 `http://127.0.0.1:8787`，只接受本機連線。跨裝置部署、Caddy 自動 HTTPS、網域、憑證輪換及資料備份，請見 [同步部署指南](deployment/README.md)。

## 本機資料與備份

預設資料位於 `data/`：

| 路徑 | 用途 |
| --- | --- |
| `bell.sqlite` | 完整教學筆記；`BELL_DATA_PATH` 可指定其他檔案位置。 |
| `settings.sqlite` | 供應商、模型、effort 與速度選擇。 |
| `knowledge.sqlite` | Repo 工作與檔案索引、筆記分段、向量及向量設定。 |
| `sync.sqlite` | 連線憑證、同步版本、待送佇列與衝突。 |
| `learning.sqlite` | 自我檢查的參考答案與作答紀錄、複習卡片排程與評分紀錄。 |
| `index-cache/` | 下載的 Git 資料與本機向量模型。 |
| `documents/` | 上傳的原始附件、檔案資訊與擷取文字；備份時須一併保存。 |

指定 `BELL_DATA_PATH` 後，其餘本機資料庫與快取放在同一個父資料夾。示範只在全新筆記資料庫初始化一次；刪除後重啟不會恢復，主動再次體驗示範會重新儲存。

備份時先正常停止本機服務，再複製整個資料目錄，包括仍存在的 SQLite `-wal`／`-shm` 同伴檔案。向量模型與 Git 快取可重新下載，但保存一起可減少重建時間。同步伺服器另有自己的資料庫／Docker volume，請依部署指南備份。Markdown 匯出不能還原完整知識庫；刪除的筆記會以 JSON 保留在 `data/trash/` 30 天以便手動救回，之後在服務啟動時永久刪除；介面沒有一般垃圾桶，請保留備份。`.env`、`data/` 與其中的同步憑證屬於私密資料，不應提交至 Git。
